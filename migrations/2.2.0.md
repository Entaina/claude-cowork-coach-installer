# Migración a 2.2.0 — Claude Code local

Se ejecuta desde el repositorio mediante UPDATE.md, después de las migraciones anteriores y de la confirmación del usuario. Fija la revisión 2.2.0 que estás aplicando; no mezcles archivos de distintas revisiones. No se copia a la instalación.

## 1. Inspección antes de escribir

Compara los siete archivos cambiados de la tabla siguiente con sus originales 2.1.0 en `migrations/2.2.0/originals/` y con la revisión destino. Resuelve todos los conflictos antes de escribir. Si un archivo coincide con el resultado esperado, no lo cambies. Si está personalizado, muestra las diferencias y acuerda la edición por bloques, conservando su contenido; no sustituyas un mapa o sistema completo. Un archivo eliminado por el usuario no se restaura automáticamente.

Los destinos nuevos son `AIOS/claude-code.md` y `AIOS/integrations/claude_code.py`. Si existen idénticos, sáltalos; si difieren, resuelve el conflicto antes de escribir. Conserva otros archivos de `AIOS/integrations/`.

## 2. Añadido y Cambiado

Copia los dos destinos nuevos que procedan y aplica únicamente estos cambios a los archivos existentes:

| Archivo | Cambio |
| --- | --- |
| `AIOS/entornos-locales.md` | Añade Code, su lector de sesiones registradas y la revisión conjunta a demanda; mantiene Cowork/GPT. |
| `AIOS/mapa-contenido.md` | Registra la guía, el adaptador y el estado técnico local de Code. |

| `AIOS/systems/proyectos-y-areas.md` | Añade Code como segunda fase de esa revisión. |

No se cambian `CLAUDE.md`, `AGENTS.md`, `ME.md`, las plantillas, los criterios de los learners ni las otras skills. La entrevista nueva se aplica solo a instalaciones nuevas; no repitas la de usuarios existentes. Conserva íntegros proyectos, áreas, conocimiento y diarios.

## 3. Integración nativa opcional en el entorno actual

Actualizar estos archivos no autoriza cambiar la configuración de otra aplicación. En Cowork y GPT no ejecutes el adaptador de Code; sus programaciones se conservan.

Si el usuario ha pedido activar Claude Code en esta carpeta, ese alcance local ya está elegido. Sigue `AIOS/claude-code.md`: comprueba Python/zona horaria, muestra la vista previa y aplica con la autorización correspondiente. Fusiona la configuración con el instalador, no copiando un settings.json del repositorio. Ante un wrapper personalizado o un ajuste incompatible, conserva lo existente y resuelve el conflicto antes de aplicar. No cambies configuración global, MCP, permisos ni programaciones. Si no se solicita activar Code, o falta una capacidad, la integración queda pendiente y la migración de archivos puede terminar; no la declares verificada.

Abre una sesión nueva para comprobar CLAUDE.md, skills y hook. Prueba `/coach-review` sobre datos autorizados y distingue esta ejecución manual de cualquier programación. Los wrappers antiguos de otros hosts se refrescan solo con su alcance autorizado; nunca se borran ni se reemplazan automáticamente.

## 4. Verificación y versión

Comprueba las rutas nuevas, que los siete cambios acordados están aplicados y que los archivos protegidos conservan su contenido. Los dos arranques deben conservarse tal como estaban; una excepción local documentada a su igualdad no se corrige en esta migración. Si hay conflictos de archivos pendientes, no avances la versión. Solo al terminar deja que UPDATE.md escriba `2.2.0` en `AIOS/VERSION.md`.

La versión acredita la migración de archivos, no que el usuario haya elegido activar Code ni que su programación haya funcionado. Comunica por separado esos estados. Conserva originales y migraciones históricas sin cambios.
