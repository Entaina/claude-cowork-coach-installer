# Migración a 2.3.1 — Claude Code en Windows sin Git ni Python manual

Se ejecuta desde el repositorio mediante UPDATE.md, después de las migraciones anteriores y de la confirmación del usuario. Fija la revisión 2.3.1 que estás aplicando; no mezcles archivos de distintas revisiones. No se copia a la instalación.

## 1. Inspección antes de escribir

Compara los dos archivos de la tabla con sus originales 2.3.0 en `migrations/2.3.1/originals/` y con la revisión destino. Si un archivo coincide con el resultado esperado, no lo cambies. Si está personalizado, muestra las diferencias y acuerda la edición por bloques, conservando su contenido. Un archivo eliminado por el usuario no se restaura automáticamente.

## 2. Cambiado

| Archivo | Cambio |
| --- | --- |
| `AIOS/integrations/claude_code.py` | Hook `SessionStart` sin shell, con la ruta absoluta del Python que instala; sustituye el hook de texto anterior. Sin base de zonas horarias, el lector usa la hora local del sistema. |
| `AIOS/claude-code.md` | Python como paso de la instalación, que hace el agente con el OK del usuario; Git no se instala y su aviso se explica; ya no se pide `tzdata`. |

No se cambian `CLAUDE.md`, `AGENTS.md`, `ME.md`, los mapas, los sistemas ni las skills. Conserva íntegros proyectos, áreas, conocimiento y diarios.

## 3. Claude Code: refrescar el hook

Si la integración de Claude Code está activa en esta carpeta, el hook registrado por 2.2.0 o 2.3.0 llama a `python3`. En Windows, ese hook puede no haber registrado ninguna sesión. Sigue el apartado «Python» de `AIOS/claude-code.md` para obtener la ruta completa de Python, repite con ella la vista previa y aplica con la autorización correspondiente: solo cambian `.claude/settings.json` y el manifiesto local. Si el usuario modificó el hook, conserva lo existente y resuelve el conflicto antes de aplicar. Comprueba después, en una sesión nueva, que esa sesión queda registrada. En Cowork, GPT y Quick no ejecutes el adaptador.

Las sesiones que no se registraron con el hook anterior no se recuperan: la cobertura del historial empieza en la primera sesión registrada.

## 4. Verificación y versión

Comprueba que los dos cambios están aplicados y que los archivos protegidos conservan su contenido. Si hay conflictos pendientes, no avances la versión. Solo al terminar deja que UPDATE.md escriba `2.3.1` en `AIOS/VERSION.md`.

La versión acredita la migración de archivos, no que el hook haya registrado una sesión. Comunica por separado ese estado. Conserva originales y migraciones históricas sin cambios.
