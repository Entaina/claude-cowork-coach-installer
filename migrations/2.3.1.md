# Migración a 2.3.1 — Claude Code en Windows sin Git ni Python manual

Se ejecuta desde el repositorio mediante UPDATE.md, después de las migraciones anteriores y de la confirmación del usuario. Fija la revisión 2.3.1 que estás aplicando; no mezcles archivos de distintas revisiones. No se copia a la instalación.

## 1. Inspección antes de escribir

Compara los tres archivos de la tabla con sus originales 2.3.0 en `migrations/2.3.1/originals/` y con la revisión destino. Resuelve todos los conflictos antes de escribir. Si un archivo ya coincide con el destino, no lo cambies. Un archivo eliminado por el usuario no se restaura automáticamente.

- `AIOS/integrations/claude_code.py` es código, no un mapa: **no lo edites por líneas**. Si coincide con su original 2.3.0, sustitúyelo entero por el de la revisión 2.3.1. Si difiere, el usuario lo modificó: enséñale que hay cambios y no lo toques hasta que decida.
- `AIOS/claude-code.md` y `AIOS/entornos-locales.md`: si coinciden con su original, sustitúyelos enteros por los de la revisión 2.3.1. Si están personalizados, aplica solo los cambios de la tabla con las reglas de **Cambiado** de UPDATE.md.

## 2. Cambiado

| Archivo | Cambio |
| --- | --- |
| `AIOS/integrations/claude_code.py` | Hook `SessionStart` sin shell, con la ruta absoluta del Python que instala; sustituye el hook de texto anterior. Sin base de zonas horarias, el lector usa la hora local del sistema. |
| `AIOS/claude-code.md` | Apartado «Python»: el agente comprueba Python y, si falta, lo instala con el OK del usuario. Git no se instala y su aviso se explica como normal. Ya no se pide `tzdata`. Ruta de Python para el lector. «Claude Code» sin «CLI». |
| `AIOS/entornos-locales.md` | «Claude Code» sin «CLI» en la lista y en sus dos apartados; el lector del historial remite a la ruta de Python de `AIOS/claude-code.md` si `python3` no responde. |

No se cambian `CLAUDE.md`, `AGENTS.md`, `ME.md`, los mapas, los sistemas ni las skills. Conserva íntegros proyectos, áreas, conocimiento y diarios.

## 3. Claude Code: refrescar el hook

Si la integración de Claude Code está activa en esta carpeta, el hook registrado por 2.2.0 o 2.3.0 llama a `python3`. En Windows, ese hook puede no haber registrado ninguna sesión. Sigue el apartado «Python» de `AIOS/claude-code.md` para obtener la ruta completa de Python (instálalo si falta, con el OK del usuario), repite con ella la vista previa y aplica con la autorización correspondiente: solo cambian `.claude/settings.json` y el manifiesto local. Si el usuario modificó el hook, conserva lo existente y resuelve el conflicto antes de aplicar. Comprueba después, en una sesión nueva, que esa sesión queda registrada. En Cowork, GPT y Quick no ejecutes el adaptador.

Si en esta misma actualización vienes de una versión anterior a 2.3.0, la reinstalación que pide la migración 2.3.0 se hace aquí, una sola vez y con el adaptador 2.3.1. Si allí falló por `python3`, no lo cuentes como conflicto: este paso lo resuelve.

Las sesiones que no se registraron con el hook anterior no se recuperan: la cobertura del historial empieza en la primera sesión registrada.

## 4. Verificación y versión

Comprueba que los tres cambios están aplicados y que los archivos protegidos conservan su contenido. Si hay conflictos pendientes, no avances la versión. Solo al terminar deja que UPDATE.md escriba `2.3.1` en `AIOS/VERSION.md`.

La versión acredita la migración de archivos, no que el hook haya registrado una sesión. Comunica por separado ese estado. Conserva originales y migraciones históricas sin cambios.
